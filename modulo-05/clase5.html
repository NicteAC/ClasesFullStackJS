El modelo conceptual
de Entidad-Relación

Enfoque utilizado para representar de manera abstracta y visual la estructura de datos y sus relaciones.

¿Qué es el modelo ER?

Herramienta gráfica para diseñar bases de datos antes de escribir código. Facilita la comunicación entre diseñadores, desarrolladores y usuarios finales.

🏷️

Bloque 4

Atributos e
identificadores únicos

Los atributos describen las entidades. Los identificadores únicos las distinguen de todas las demás.

Características de los atributos

📝

Descripción de datos

Describen los datos de una entidad. Ejemplo: nombre, precio, fecha.

🎨

Tipos de datos

Texto, números, fechas, booleanos. Cada atributo tiene un tipo específico.

🔑

Identificación única

Algunos atributos son claves primarias que identifican registros de forma única.

🔑 Identificador único (Clave Primaria)

Atributo especial o combinación de atributos que identifica de forma única cada registro de una tabla.

CREATE TABLE Productos ( producto_id INT AUTO_INCREMENT PRIMARY KEY, -- Identificador único nombre VARCHAR(100) NOT NULL, precio DECIMAL(10, 2), stock INT DEFAULT 0 );

💡 Ejemplos típicos: id_producto, id_usuario, ISBN, RUT, SKU.

AE 5.2 · Bloque 5

Entidades débiles
y fuertes

Las entidades pueden existir por sí mismas (fuertes) o depender de otra entidad (débiles) para su identificación.

Fuertes vs Débiles

💪 Entidad Fuerte

Existe por sí misma. Tiene identificador propio.

  • Independiente
  • Identificador único propio (PK)
  • Puede tener relaciones con otras

Ejemplos: Cliente, Empleado, Producto

vs

🔗 Entidad Débil

Depende de otra entidad para existir.

  • Dependiente de una fuerte
  • Identificador combinado (parcial + FK)
  • Relación uno a uno con la propietaria

Ejemplos: DetalleOrden, CopiaLibro

Ejemplo: Libro (fuerte) y Copia (débil)

-- Entidad FUERTE: Libro (existe por sí mismo) CREATE TABLE Libros ( libro_id INT AUTO_INCREMENT PRIMARY KEY, titulo VARCHAR(150) NOT NULL, autor VARCHAR(100), isbn VARCHAR(20) UNIQUE ); -- Entidad DÉBIL: Copia (necesita un libro para existir) CREATE TABLE CopiasLibro ( libro_id INT NOT NULL, -- Parte de la PK compuesta num_copia INT NOT NULL, -- Parte de la PK compuesta estado VARCHAR(20) DEFAULT 'disponible', PRIMARY KEY (libro_id, num_copia), FOREIGN KEY (libro_id) REFERENCES Libros(libro_id) ON DELETE CASCADE );

Bloque 7

Reglas de transformación

Pautas para convertir un modelo conceptual en un modelo relacional concreto.

Las 5 reglas clave

1️⃣ Entidades → Tablas

Cada entidad del modelo ER se convierte en una tabla del modelo relacional.

2️⃣ Atributos → Columnas

Cada atributo de la entidad se convierte en una columna de la tabla.

3️⃣ Identificadores → PK

El identificador único se convierte en clave primaria (PRIMARY KEY).

4️⃣ Relaciones → FK

Las relaciones entre entidades se implementan con claves foráneas (FOREIGN KEY).

5️⃣ Nomenclatura consistente

Elegir nombres claros según las convenciones del sistema (snake_case, camelCase, singular/plural).

Bloque 8

Normalización de datos

Proceso que elimina la redundancia y mejora la eficiencia e integridad de los datos.

¿En qué consiste normalizar?

Organizar los datos en tablas de manera que se minimice la duplicación y se eviten problemas de actualización y pérdida de consistencia.

1NF

1️⃣

Eliminar valores repetidos. Cada celda contiene un solo valor atómico.

2NF

2️⃣

Eliminar dependencias parciales. Todo depende de la PK completa.

3NF

3️⃣

Eliminar dependencias transitivas entre columnas no clave.

1️⃣ Primera Forma Normal (1NF)

Cada columna contiene un solo valor atómico
