¿Qué es Node.js?

Es un entorno de ejecución para JavaScript construido sobre el motor V8 de Chrome, que nos permite correr JS fuera del navegador.

🌐

Backend

Construye servidores web, APIs REST y aplicaciones en tiempo real.

⚡

Asincrónico

Modelo no bloqueante basado en eventos: alto rendimiento con pocos recursos.

🪟 Instalación en Windows

Paso a paso

  • Ir a https://nodejs.org y descargar la versión LTS (recomendada).
  • Ejecutar el instalador .msi descargado.
  • Aceptar la licencia y dejar las opciones por defecto (incluye npm y añade a PATH).
  • Finalizar y reiniciar la terminal para que reconozca el PATH.
PowerShell — Verificación
PS C:\Users\Carola> node -v v22.12.0 PS C:\Users\Carola> npm -v 10.9.0

📁 Creación de un proyecto Node.js

Estructura mínima para empezar

Terminal — Inicializando proyecto
# 1. Crear carpeta y entrar en ella $ mkdir mi-proyecto $ cd mi-proyecto # 2. Inicializar el proyecto (genera package.json) $ npm init -y # 3. Abrir en VS Code $ code .

El flag -y acepta todas las opciones por defecto. Sin él, npm te pregunta nombre, versión, autor, etc.

📄 El archivo package.json

La cédula de identidad de tu proyecto

{ "name": "mi-proyecto", "version": "1.0.0", "description": "", "main": "index.js", "scripts": { "test": "echo \"Error: no test specified\" && exit 1" }, "keywords": [], "author": "", "license": "ISC" }

Aquí se registran dependencias, scripts y metadatos del proyecto.

console.log("¡Hola, Mundo desde Node.js!"); console.log("Directorio:", process.cwd()); console.log("Versión:", process.version);

Terminal
$ node index.js ¡Hola, Mundo desde Node.js! Directorio: /home/carola/mi-proyecto Versión: v22.12.0

¿Qué es Express.js?

Un framework minimalista y flexible para Node.js que facilita la creación de servidores web y APIs.

🎯

Rutas simples

Define endpoints HTTP con una sintaxis clara: app.get(), app.post()...

🧩

Middleware

Ejecuta lógica entre la petición y la respuesta: logs, auth, validación...

🌍

Estándar de la industria

Miles de empresas lo usan en producción. Base para NestJS y otros.

📥 Instalación de Express

Un solo comando

Terminal — Instalando Express
$ npm install express added 69 packages in 3s ✓ express agregado a dependencies

Express queda registrado en package.json dentro de dependencies y sus archivos se guardan en node_modules/.

"dependencies": { "express": "^4.21.1" }

🚀 Nuestro primer servidor Express

Archivo server.js:

const express = require('express'); const app = express(); const PORT = 3000; // Ruta raíz app.get('/', (req, res) => { res.send('Hola Mundo desde Express 🚀'); }); app.listen(PORT, () => { console.log(`Servidor en http://localhost:${PORT}`); });

Ejecutar: node server.js → abrir http://localhost:3000

📂 Estructura básica de un proyecto Express

mi-proyecto/ ├── node_modules/ # Paquetes instalados ├── public/ # Archivos estáticos │ ├── index.html │ └── styles.css ├── server.js # Punto de entrada ├── package.json # Metadatos + deps ├── package-lock.json # Versiones exactas └── .gitignore # Ignora node_modules

🎯 Puntos clave

  • node_modules/ nunca se sube a Git (es pesado).
  • package.json permite reinstalar todo con npm install.
  • public/ se sirve con express.static().
  • El punto de entrada se declara en "main" del package.json.

Introducción a npm

Node Package Manager: el gestor de paquetes por defecto de Node.js.

📄

package.json

Archivo de configuración donde se registran las dependencias del proyecto.

📁

node_modules/

Carpeta donde npm guarda todos los paquetes instalados. Se ignora en Git.

🔒

package-lock.json

Bloquea las versiones exactas de cada dependencia para instalaciones reproducibles.

⚡ Comandos esenciales de npm

npm init -y

Crea un package.json con valores por defecto.

npm install <paquete>

Instala un paquete y lo agrega a dependencies.

npm install -D <paquete>

Lo instala como devDependency (solo desarrollo).

npm install -g <paquete>

Instalación global (disponible en todo el sistema).

npm uninstall <paquete>

Elimina un paquete del proyecto.

npm update

Actualiza dependencias según semver.

npm list

Muestra el árbol de paquetes instalados.

npm run <script>

Ejecuta un script definido en package.json.

🔥 node --watch: modo desarrollo nativo

Desde Node.js 22 LTS es ESTABLE — sin instalar nada extra.

✅ Uso básico

# Reinicia el proceso al detectar # cambios en el archivo o sus imports $ node --watch server.js

📍 Watch de una carpeta específica

$ node --watch-path=./src server.js

🎯 Script en package.json

"scripts": { "start": "node server.js", "dev": "node --watch server.js" }

Luego se ejecuta con:

$ npm run dev

🔄 Nodemon: la alternativa clásica

Antes de --watch nativo, nodemon era el estándar. Sigue siendo útil por su configurabilidad. SIGUE VIGENTE

Instalación

# como devDependency (recomendado) $ npm install --save-dev nodemon # o global $ npm install -g nodemon

Uso

$ nodemon server.js

¿Cuándo elegir cada uno?

  • --watch Proyectos nuevos, sin dependencias extra.
  • nodemon Cuando necesitas config avanzada: extensiones a vigilar, delay, ignore, comandos custom.
  • Ambos hacen básicamente lo mismo: reinicio automático al detectar cambios.

⏱️ Bloqueante vs No Bloqueante

🛑 Bloqueante (sync)

La ejecución se detiene hasta que la operación termina.

Cada tarea debe completarse antes de que empiece la siguiente.

Ejemplo: fs.readFileSync()

✅ No bloqueante (async)

Node delega la operación y sigue ejecutando otro código.

Cuando la operación termina, se llama al callback / se resuelve la promesa.

Ejemplo: fs.readFile()

🎯 El modelo no bloqueante es la clave del rendimiento de Node.js.

🛑 Código bloqueante

const fs = require('fs'); console.log("1. Antes de leer el archivo"); const data = fs.readFileSync('archivo.txt', 'utf8'); console.log("2. Contenido:", data); console.log("3. Después de leer");
Salida
1. Antes de leer el archivo 2. Contenido: Hola desde el archivo 3. Después de leer

Los logs salen estrictamente en orden: 1 → 2 → 3.

✅ Código no bloqueante

const fs = require('fs'); console.log("1. Antes de leer el archivo"); fs.readFile('archivo.txt', 'utf8', (err, data) => { console.log("2. Contenido:", data); }); console.log("3. Después de programar la lectura");
Salida
1. Antes de leer el archivo 3. Después de programar la lectura 2. Contenido: Hola desde el archivo

El 3 sale antes que el 2: Node no espera, sigue ejecutando. Ese es el poder de la asincronía.

♻️ Ciclo de vida de un proceso Node

Node ejecuta en un solo hilo principal, con la ayuda de libuv para tareas pesadas en segundo plano.

🌀 Modelo

  • Un solo hilo para JS.
  • Event Loop coordina todo.
  • libuv maneja operaciones I/O en threads del SO.
  • No bloquear el hilo principal = alto rendimiento.

🛠️ Manejar procesos

  • ps · tasklist (Win) → listar procesos.
  • kill <PID> → detener un proceso.
  • Ctrl+C en terminal → detener el proceso Node en curso.
  • process.exit(0) → salir desde el código.

yargs: CLIs en Node.js

Un paquete que nos permite construir herramientas de línea de comandos profesionales, con argumentos, opciones y ayuda automática.

🎯

Argumentos posicionales

node app.js sumar 5 3

🚩

Flags y opciones

--nombre="Carola"
-v · --verbose

📖

Ayuda automática

Genera --help con la documentación de tus comandos.

📥 Instalación y uso básico de yargs

1. Instalar

$ npm install yargs

2. Ejecutar con args

$ node app.js --nombre="Carola" --edad=30
Salida
Hola Carola, tienes 30 años 👋

3. Código básico (app.js)

const yargs = require('yargs'); const argv = yargs(process.argv.slice(2)) .option('nombre', { alias: 'n', type: 'string', demandOption: true }) .option('edad', { type: 'number', default: 18 }) .help() .argv; console.log(`Hola ${argv.nombre}, tienes ${argv.edad} años 👋`);

⚙️ yargs con comandos

Crea sub-comandos como Git (git commit, git push):

const yargs = require('yargs'); yargs(process.argv.slice(2)) .command('sumar <a> <b>', 'Suma dos números', () => {}, (argv) => { console.log(`Resultado: ${argv.a + argv.b}`); }) .command('saludar <nombre>', 'Saluda por nombre', () => {}, (argv) => { console.log(`¡Hola ${argv.nombre}! 👋`); }) .demandCommand(1) .help() .parse();
Terminal — Uso
$ node app.js sumar 5 3 Resultado: 8 $ node app.js saludar Carola ¡Hola Carola! 👋 $ node app.js --help
