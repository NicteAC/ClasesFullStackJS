¿Qué es un servidor web?

Un programa que escucha peticiones HTTP de clientes (navegadores, apps) y responde con contenido: HTML, JSON, imágenes, etc.

📥

Recibe

Peticiones del cliente vía HTTP: GET /, POST /login...

⚙️

Procesa

Ejecuta lógica: consulta datos, valida, transforma información.

📤

Responde

Envía HTML, JSON u otro contenido al cliente que lo solicitó.

Con Express, todo esto se vuelve muy fácil de escribir.

⚙️ Configuración inicial

Preparando el proyecto

Terminal — Setup
# 1. Verificar Node.js $ node -v v22.12.0 # 2. Crear proyecto $ mkdir mi-servidor $ cd mi-servidor $ npm init -y # 3. Instalar Express $ npm install express # 4. Abrir en VS Code $ code .

Ya tenemos la base para crear el servidor.

🚀 Servidor básico con Express

Archivo server.js:

const express = require('express'); const app = express(); const PORT = 3000; // Definir una ruta app.get('/', (req, res) => { res.send('¡Bienvenido a mi servidor Express!'); }); // Iniciar el servidor app.listen(PORT, () => { console.log(`Servidor en http://localhost:${PORT}`); });

Ejecutar: node server.js

▶️ Ejecutar y probar

1. Iniciar el servidor

Terminal
$ node server.js Servidor en http://localhost:3000

💡 Para detenerlo: Ctrl + C

💡 Modo dev: node --watch server.js

2. Abrir en el navegador

🌐 http://localhost:3000

¡Bienvenido a mi servidor Express!

✅ El servidor responde con lo que definimos en res.send()

📡 Métodos HTTP

Cada método tiene un propósito específico

GET

Obtener datos

Leer un recurso sin modificarlo.
Ej: cargar una página, listar productos.

POST

Crear datos

Enviar información nueva al servidor.
Ej: registro de usuario, envío de formulario.

PUT

Actualizar datos

Modificar un recurso existente.
Ej: editar perfil, cambiar contraseña.

DELETE

Eliminar datos

Borrar un recurso del servidor.
Ej: eliminar cuenta, borrar producto.

🛣️ Definir rutas en Express

Sintaxis: app.metodo(ruta, callback)

// GET: página principal app.get('/', (req, res) => { res.send('Hola desde /'); }); // GET: página "Acerca de" app.get('/about', (req, res) => { res.send('<h1>Acerca de nosotros</h1>'); }); // POST: recibir datos app.post('/contacto', (req, res) => { res.send('Mensaje recibido'); });

req: petición del cliente · res: respuesta del servidor

🎯 Rutas con parámetros

Podemos capturar valores dinámicos desde la URL con :parametro

// Parámetros de ruta app.get('/saludo/:nombre', (req, res) => { const { nombre } = req.params; res.send(`¡Hola ${nombre}!`); }); // Query strings: ?edad=30&pais=CL app.get('/buscar', (req, res) => { const { edad, pais } = req.query; res.send(`Edad: ${edad}, País: ${pais}`); });

/saludo/Carola → "¡Hola Carola!"

/buscar?edad=30&pais=CL → "Edad: 30, País: CL"

📁 Contenido estático

Servir imágenes, CSS, JS y HTML desde una carpeta con una sola línea:

app.use(express.static('public'));

📂 Estructura

mi-servidor/ ├── server.js ├── package.json └── public/ ├── index.html ├── styles.css └── img/ └── logo.png

🌐 URLs generadas

  • /index.html → public/index.html
  • /styles.css → public/styles.css
  • /img/logo.png → public/img/logo.png

Con prefijo:

app.use('/assets', express.static('public'));

🎨 Datos dinámicos en la respuesta

Podemos armar respuestas HTML con datos del servidor. Primera aproximación (sin motor de plantillas):

app.get('/perfil', (req, res) => { const usuario = { nombre: "Carola", edad: 25, ciudad: "Santiago" }; res.send(` <h1>Perfil de ${usuario.nombre}</h1> <p>Edad: ${usuario.edad} años</p> <p>Ciudad: ${usuario.ciudad}</p> `); });

⚠️ Esto funciona pero se vuelve insostenible con páginas grandes. Necesitamos algo mejor…

🧩 ¿Por qué modularizar las vistas?

😰 Sin modularización

  • El HTML se repite en cada ruta.
  • Cambiar el menú requiere editar 20 archivos.
  • El código del servidor mezcla lógica y presentación.
  • Difícil de mantener y probar.

😎 Con motor de plantillas

  • Plantillas reutilizables.
  • Cabecera y pie de página en un solo lugar.
  • Separación clara: lógica vs vista.
  • Datos dinámicos con sintaxis simple: {{nombre}}

¿Qué es un motor de plantillas?

Una herramienta que combina HTML estático con datos dinámicos para generar la página final.

❌ Sin motor

<h1>Bienvenido</h1> <p>Usuario: Juan</p>

Solo sirve para un usuario específico. Rígido.

✅ Con motor de plantillas

<h1>Bienvenido</h1> <p>Usuario: {{nombre}}</p>

Reutilizable con cualquier usuario. Dinámico.

⚖️ Handlebars vs EJS vs Pug

Los 3 motores más populares

Motor Sintaxis Ejemplo Ventajas
Handlebars {{variable}} Hola {{nombre}} Simple, modular, muy usado
EJS <%= variable %> Hola <%= nombre %> Similar a HTML, permite JS embebido
Pug Indentación h1= nombre Sintaxis reducida, muy legible

🎯 Hoy trabajaremos con Handlebars (HBS) por su simplicidad y sintaxis clara.

📥 Instalación de Handlebars

Un solo comando:

Terminal
$ npm install hbs added 5 packages in 2s ✓ hbs agregado a dependencies

hbs es el wrapper oficial de Handlebars para Express. Existe también express-handlebars, más completo pero un poco más complejo.

"dependencies": { "express": "^4.21.1", "hbs": "^4.2.0" }

⚙️ Configurar Handlebars en Express

const express = require('express'); const hbs = require('hbs'); const path = require('path'); const app = express(); // Configurar HBS como motor de plantillas app.set('view engine', 'hbs'); // Indicar dónde están las vistas (por defecto: /views) app.set('views', path.join(__dirname, 'views')); app.listen(3000, () => console.log('Servidor listo'));

Con esto, Express sabe que los archivos .hbs son plantillas.

📂 Estructura del proyecto con Handlebars

mi-servidor/ ├── node_modules/ ├── public/ # estáticos │ ├── styles.css │ └── logo.png ├── views/ # plantillas HBS │ ├── home.hbs │ ├── perfil.hbs │ └── partials/ # fragmentos │ ├── header.hbs │ └── footer.hbs ├── server.js └── package.json

🎯 Convenciones

  • Las plantillas se guardan en views/.
  • Los archivos usan extensión .hbs.
  • Los fragmentos reutilizables van en views/partials/.
  • El motor las encuentra automáticamente.

🖼️ Primera vista con res.render

1. Ruta en server.js

app.get('/', (req, res) => { res.render('home', { nombre: 'Carola', edad: 25 }); });

res.render() busca views/home.hbs y le pasa los datos.

2. Plantilla views/home.hbs

<!DOCTYPE html> <html> <head><title>Inicio</title></head> <body> <h1>Hola, {{nombre}}</h1> <p>Edad: {{edad}} años</p> </body> </html>

Las llaves dobles {{}} son marcadores.

🔁 Iterar listas con {{#each}}

server.js

app.get('/productos', (req, res) => { res.render('productos', { titulo: 'Catálogo', productos: [ { nombre: 'Laptop', precio: 899 }, { nombre: 'Mouse', precio: 25 }, { nombre: 'Teclado', precio: 75 } ] }); });

views/productos.hbs

<h1>{{titulo}}</h1> <ul> {{#each productos}} <li> {{nombre}} - ${{precio}} </li> {{/each}} </ul>

Dentro del each, this es el elemento actual.

🔀 Condicionales con {{#if}}

Sintaxis básica

{{#if usuario}} <p>Hola, {{usuario.nombre}}</p> {{else}} <a href="/login">Iniciar sesión</a> {{/if}}

Con {{#unless}}

{{#unless productos}} <p>No hay productos</p> {{/unless}} {{#each productos}} <li>{{nombre}}</li> {{/each}}

unless es lo opuesto a if: se ejecuta cuando el valor es falsy (undefined, null, false, 0, "", []).

🛠️ Helpers personalizados

Funciones que transforman datos dentro de la vista.

server.js

// Helper: mayúsculas hbs.registerHelper('gritar', (texto) => { return texto.toUpperCase(); }); // Helper: formatear precio hbs.registerHelper('clp', (valor) => { return valor.toLocaleString('es-CL', { style: 'currency', currency: 'CLP' }); });

En la plantilla

<h1>{{gritar titulo}}</h1> <!-- "OFERTAS DEL MES" --> <p>Precio: {{clp precio}}</p> <!-- "Precio: $12.990" --> {{#each productos}} <li>{{nombre}} - {{clp precio}}</li> {{/each}}

🧩 Páginas parciales (partials)

Fragmentos reutilizables como header y footer.

1. Registrar en server.js

hbs.registerPartials( __dirname + '/views/partials' );

2. Crear partials/header.hbs

<header> <h1>Mi Sitio</h1> <nav> <a href="/">Inicio</a> <a href="/about">Nosotros</a> </nav> </header>

3. Usar en cualquier vista

{{> header}} <main> <h2>Página principal</h2> <p>Bienvenido a nuestro sitio</p> </main> {{> footer}}

La sintaxis {{> nombre}} incluye el parcial.

🎁 Parciales con datos propios

Podemos pasarle contexto a un parcial:

Parcial partials/card.hbs

<div class="card"> <h3>{{titulo}}</h3> <p>{{descripcion}}</p> </div>

Uso en la vista principal

{{> card titulo="Node.js" descripcion="Backend con JS"}} {{> card titulo="Express" descripcion="Framework web"}} <!-- Con iteración --> {{#each cursos}} {{> card this}} {{/each}}

💡 Súper útil para componentes reutilizables — cards, botones, alertas.

🎬 Ejemplo integrado

Todo junto: partials + each + helper

server.js

hbs.registerPartials(__dirname + '/views/partials'); hbs.registerHelper('clp', (v) => v.toLocaleString('es-CL', { style:'currency',currency:'CLP' })); app.get('/tienda', (req, res) => { res.render('tienda', { titulo: 'Mi Tienda', productos: [ {nombre:'Laptop', precio:899000}, {nombre:'Mouse', precio:15990} ] }); });

views/tienda.hbs

{{> header}} <h1>{{titulo}}</h1> {{#if productos}} <ul> {{#each productos}} <li> {{nombre}} - {{clp precio}} </li> {{/each}} </ul> {{else}} <p>Sin productos</p> {{/if}} {{> footer}}
