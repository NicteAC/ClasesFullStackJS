¿Qué es NPM?

Node Package Manager: el gestor de paquetes por defecto de Node.js. Nos permite instalar, compartir y administrar librerías de código de terceros.

3M+
Paquetes disponibles en el registro público
2010
Año de nacimiento, junto a Node.js
CLI
Herramienta de línea de comandos + registro online

Se instala automáticamente con Node.js — npm -v para verificar.

🎯 Principales funciones de NPM

📥

Gestión de paquetes

Instalar, actualizar y eliminar librerías de terceros con un solo comando.

🔢

Control de versiones

Especificar y bloquear versiones para garantizar consistencia entre entornos.

⚙️

Automatización de tareas

Ejecutar scripts personalizados en package.json: npm run dev, npm test, etc.

🌍

Publicación de paquetes

Publicar nuestras propias librerías en npmjs.com para uso público o privado.

📥 Instalación de paquetes

Sintaxis básica:

npm install <paquete>
Terminal — Ejemplos
# Instalar un paquete de producción $ npm install express # Instalar varios a la vez $ npm install express dotenv cors # Instalar como dependencia de desarrollo $ npm install --save-dev nodemon $ npm install -D jest # abreviatura # Instalar una versión específica $ npm install express@4.18.2 # Alias corto de install $ npm i lodash

🌐 Paquetes locales vs globales

LOCAL

Por proyecto

$ npm install express
  • Se guarda en ./node_modules/
  • Solo disponible en ese proyecto
  • Se registra en package.json
  • Es lo que usamos casi siempre
GLOBAL

Todo el sistema

$ npm install -g http-server
  • Se guarda en carpeta global del sistema
  • Disponible como comando en cualquier lugar
  • NO se registra en package.json
  • Solo para herramientas CLI

💡 Alternativa moderna: npx paquete ejecuta un paquete sin instalarlo globalmente.

🔄 Actualizar paquetes

Terminal
# Actualizar TODAS las dependencias del proyecto $ npm update # Actualizar un paquete específico $ npm update express # Ver qué paquetes tienen actualizaciones disponibles $ npm outdated Package Current Wanted Latest express 4.18.2 4.21.1 4.21.1 dotenv 16.0.3 16.4.5 16.4.5 mongoose 7.5.0 7.8.0 8.9.0 # Instalar la versión exactamente última $ npm install express@latest
⚠️ Ojo: npm update respeta el rango de versiones definido en package.json (por ejemplo ^4.18 nunca subirá a 5.x). Para saltar de versión mayor hay que hacerlo manualmente.

🗑️ Eliminar paquetes

Terminal
# Desinstalar un paquete local $ npm uninstall express # Alias cortos $ npm un express $ npm remove express $ npm rm express # Desinstalar un paquete global $ npm uninstall -g nodemon # Desinstalar varias dependencias $ npm uninstall moment jquery bootstrap

Al desinstalar, npm:

  • Elimina la carpeta del paquete en node_modules/
  • Quita la entrada del package.json
  • Actualiza package-lock.json

Módulos en Node.js

Los módulos nos permiten dividir nuestro código en archivos reutilizables y organizados.

📜 CommonJS

El sistema original y por defecto de Node.js desde su creación.

module.exports = funcion; const x = require('./x');

✨ ES Modules

El estándar moderno de JavaScript (ECMAScript 2015).

export function saludo() {} import { saludo } from './x.js';

📜 CommonJS: require y module.exports

Exportar — saludo.js

// Exportar una función module.exports = function () { return '¡Hola desde un módulo!'; };

También podemos exportar un objeto con varias cosas:

module.exports = { sumar: (a, b) => a + b, restar: (a, b) => a - b };

Importar — app.js

// Importar una función const saludo = require('./saludo'); console.log(saludo()); // → ¡Hola desde un módulo!

Con desestructuración:

const { sumar, restar } = require('./math'); console.log(sumar(2, 3)); // 5

✨ ES Modules: import y export

Requiere "type": "module" en el package.json o extensión .mjs

Exportar — saludo.js

// Named export export function saludo() { return '¡Hola desde ES Modules!'; } // Múltiples exports export const sumar = (a, b) => a + b; export const restar = (a, b) => a - b; // Default export export default function principal() { }

Importar — app.js

// Import de named exports import { saludo } from './saludo.js'; console.log(saludo()); // Varios a la vez import { sumar, restar } from './math.js'; // Default import import principal from './app.js';
💡 En ES Modules la extensión .js es obligatoria al importar archivos locales.

⚖️ CommonJS vs ES Modules

Característica CommonJS ES Modules
Sintaxis require / module.exports import / export
Extensión .js (o sin ella al importar) .js obligatoria o .mjs
Configuración Por defecto en Node Requiere "type": "module"
Carga Sincrónica Asincrónica (permite top-level await)
Uso hoy Muy común en proyectos existentes Estándar moderno, tendencia futura

🎯 En esta clase usamos CommonJS porque sigue siendo lo más común en tutoriales y proyectos activos con Express.

🌐 Paquetes externos vs archivos locales

📚 Paquetes externos (npm)

Se importan solo con el nombre, sin ruta.

const express = require('express'); const chalk = require('chalk'); const fs = require('fs'); // nativo

Node busca en node_modules/.

📁 Archivos locales

Se importan con ruta relativa (./ o ../).

const config = require('./config'); const db = require('./db/conexion'); const util = require('../lib/util');

Node los busca en tu proyecto.

Regla rápida: si empieza con ./ o ../ → archivo local. Si es solo un nombre → paquete de node_modules.

El archivo package.json

Es el corazón de cualquier proyecto Node.js. Contiene los metadatos del proyecto y todas sus dependencias.

📇

Metadatos

Nombre, versión, autor, descripción, licencia del proyecto.

🧩

Dependencias

Registro de todos los paquetes que necesita el proyecto.

⚡

Scripts

Comandos personalizados ejecutables con npm run.

Se genera con npm init o npm init -y (todo por defecto).

🔑 Propiedades principales

{ "name": "mi-proyecto", // Nombre único (kebab-case) "version": "1.0.0", // Versión semver "description": "App de tareas", // Descripción corta "main": "index.js", // Archivo principal "scripts": { // Comandos personalizados "start": "node index.js", "dev": "node --watch index.js" }, "dependencies": { // Necesarias en producción "express": "^4.21.1" }, "devDependencies": { // Solo desarrollo "nodemon": "^3.1.0" }, "author": "Carola", "license": "ISC" }

🔢 Versionado semántico (semver)

Toda versión tiene 3 números: MAJOR.MINOR.PATCH

MAJOR
Cambios que rompen compatibilidad

4.x → 5.x

MINOR
Nuevas funcionalidades compatibles

4.18 → 4.21

PATCH
Parches y arreglos de bugs

4.21.1 → 4.21.2

^4.21.1 — caret

Acepta cualquier MINOR o PATCH nuevo. Ej: 4.22.0 ✅, 5.0.0 ❌

~4.21.1 — tilde

Solo acepta nuevos PATCH. Ej: 4.21.5 ✅, 4.22.0 ❌

⚡ Scripts en package.json

Automatiza tareas repetitivas con comandos personalizados.

"scripts": { "start": "node server.js", "dev": "node --watch server.js", "test": "jest", "lint": "eslint .", "build": "webpack --mode production", "clean": "rm -rf node_modules && npm install" }
Terminal
$ npm run dev $ npm start # atajo, no requiere 'run' $ npm test # atajo, no requiere 'run' $ npm run lint

🛠️ Comandos avanzados de NPM

npm list

Muestra el árbol completo de paquetes instalados.

$ npm list --depth=0 # Solo primer nivel

npm outdated

Detecta dependencias con actualizaciones disponibles.

$ npm outdated

npm audit

Analiza vulnerabilidades de seguridad en tus dependencias.

$ npm audit $ npm audit fix # auto-fix

npm cache clean

Limpia la caché de paquetes descargados.

$ npm cache clean --force

📁 La carpeta node_modules

  • Aquí viven físicamente todos los paquetes instalados.
  • Contiene los paquetes que instalaste + sus sub-dependencias.
  • Puede pesar cientos de MB incluso en proyectos pequeños.
  • Se puede regenerar con npm install desde el package.json.
  • NUNCA se sube a Git (usa .gitignore).
mi-proyecto/ ├── node_modules/ │ ├── express/ │ │ ├── package.json │ │ ├── index.js │ │ └── lib/ │ ├── body-parser/ │ ├── cookie-parser/ │ └── ... (200+ carpetas) ├── package.json ├── package-lock.json └── .gitignore
# .gitignore node_modules/ .env *.log

🔒 package-lock.json

Registra las versiones EXACTAS instaladas — reproducibilidad total entre entornos.

package.json

"dependencies": { "express": "^4.21.1" }

"Quiero cualquier 4.x mayor a 4.21.1"

package-lock.json

"express": { "version": "4.21.2", "resolved": "https://...", "integrity": "sha512-..." }

"Instalé exactamente 4.21.2, este es el hash"

✅ Debe subirse a Git — garantiza que todo el equipo tenga las mismas versiones.

🎨 Tipos de dependencias

dependencies

Producción

Necesarias para que la app funcione.

Ej: express, mongoose, dotenv

$ npm install express
devDependencies

Desarrollo

Solo útiles mientras desarrollas.

Ej: nodemon, jest, eslint, prettier

$ npm install -D nodemon
peerDependencies

Compañeras

El usuario final debe instalarlas él mismo.

Ej: un plugin de React requiere react

optionalDependencies

Opcionales

Si fallan al instalar, no rompen el proyecto.

Ej: paquetes específicos de un SO

🚀 package.json avanzado

{ "name": "mi-app", "version": "1.0.0", "engines": { // Versiones requeridas "node": ">=20.0.0", "npm": ">=10.0.0" }, "type": "module", // Usar ES Modules "dependencies": { ... }, "devDependencies": { ... }, "peerDependencies": { "react": "^18.0.0" }, "optionalDependencies": { "fsevents": "^2.3.3" // Solo macOS }, "scripts": { "clean": "rm -rf node_modules && npm install", "predev": "echo 'Iniciando modo dev...'", // hook "dev": "node --watch server.js" } }

Los prefijos pre y post ejecutan hooks automáticos (ej: predev corre antes de dev).

🏗️ Estrategias de modularización

Un buen proyecto Node se organiza en capas:

mi-app/ ├── config/ # Variables entorno │ └── db.js ├── routes/ # Endpoints │ ├── users.js │ └── products.js ├── controllers/ # Lógica de negocio │ ├── userController.js │ └── productController.js ├── models/ # Modelos de datos ├── utils/ # Funciones auxiliares ├── server.js └── package.json

🎯 Beneficios

  • Separación de responsabilidades: cada archivo hace una cosa.
  • Testeable: podés probar módulos por separado.
  • Escalable: agregar features sin tocar todo.
  • Colaborativo: menos conflictos en equipo.
  • Reutilizable: los módulos sirven para otros proyectos.

💡 Ejemplo práctico de modularización

utils/math.js

const sumar = (a, b) => a + b; const restar = (a, b) => a - b; const multiplicar = (a, b) => a * b; module.exports = { sumar, restar, multiplicar };

utils/formato.js

module.exports.clp = (v) => v.toLocaleString('es-CL', { style: 'currency', currency: 'CLP' });

index.js

const { sumar, multiplicar } = require('./utils/math'); const { clp } = require('./utils/formato'); const total = multiplicar(150, 1990); console.log(`Total: ${clp(total)}`); // → Total: $298.500

Cada módulo hace una sola cosa, y index.js los combina.

✅ Buenas prácticas con NPM

👍 Hacer

  • Usar -D para dependencias de desarrollo.
  • Commitear package-lock.json.
  • Ejecutar npm audit regularmente.
  • Definir "engines" para la versión de Node.
  • Documentar los scripts en el README.
  • Revisar el tamaño y salud de los paquetes antes de instalar.

👎 Evitar

  • Subir node_modules/ a Git.
  • Instalar todo con -g sin necesidad.
  • Modificar archivos dentro de node_modules/.
  • Ignorar advertencias de vulnerabilidad.
  • Mezclar CommonJS y ES Modules sin cuidado.
  • Instalar dependencias "por si acaso" sin usarlas.
