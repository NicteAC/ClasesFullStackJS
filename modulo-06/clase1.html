AE 1.1 · Bloque 1
Node.js

¿Qué es Node.js?

Entorno de ejecución de JavaScript basado en el motor V8 de Google Chrome, para ejecutar código en el servidor.

📜 Historia y evolución

👨‍💻

Creado en 2009

Por Ryan Dahl con el objetivo de ofrecer una alternativa eficiente y no bloqueante para manejar múltiples conexiones simultáneas.

⚡

Motor V8

Usa el mismo motor de JavaScript que Google Chrome, lo que le da un rendimiento excepcional.

🌐

Del cliente al servidor

Antes JavaScript solo vivía en el navegador. Node.js lo llevó al servidor.

📈

Estándar en la industria

Usado por Netflix, PayPal, LinkedIn, Uber, NASA, entre miles más.

✨ Características de Node.js

⚡

Asíncrono y No Bloqueante

Usa eventos y promesas para manejar tareas sin bloquear la ejecución.

🚀

Motor V8

Optimizado para ejecutar JavaScript con alto rendimiento.

📦

Ecosistema NPM

Más de 1 millón de paquetes y módulos disponibles.

🔧

Microservicios

Facilita la creación de aplicaciones escalables.

💻 Tu primer código en Node.js

Node.js ejecuta JavaScript fuera del navegador, directamente en tu computador.

// archivo: app.js console.log("Hola desde Node.js"); // Ejecutar desde terminal: // $ node app.js

💡 A diferencia del navegador, Node.js no tiene DOM, pero sí tiene acceso al sistema de archivos, red y procesos.

¿Qué podemos hacer con Node.js?

🌐

Servidores web

Aplicaciones web completas del lado del servidor

🔌

APIs REST

Interfaces para conectar frontends con datos

💬

Tiempo real

Chats, notificaciones, sockets bidireccionales

⌨️

CLIs

Aplicaciones de línea de comandos

📁

Manejo de archivos

Lectura, escritura y procesamiento de archivos

🎬

Streaming

Video, audio y contenido bajo demanda

🎁 Beneficios de Node.js

⚡

Eficiencia

Modelo no bloqueante que maneja múltiples solicitudes sin sobrecargar el sistema.

📈

Escalabilidad

Ideal para aplicaciones que requieren alta concurrencia.

📦

Ecosistema NPM

Más de 1 millón de módulos disponibles listos para usar.

🖥️ Servidor básico con Node.js puro

const http = require('http'); const servidor = http.createServer((req, res) => { res.writeHead(200, { 'Content-Type': 'text/plain' }); res.end('Hola desde el servidor Node.js!'); }); servidor.listen(3000, () => { console.log('Servidor corriendo en http://localhost:3000'); });

⚠️ Este es Node.js puro. Funciona, pero para aplicaciones reales usaremos Express que lo simplifica muchísimo.

Bloque 2
Express.js

¿Qué es Express.js?

Framework minimalista para Node.js que facilita la creación de aplicaciones web y APIs.

🎁 Ventajas de Express sobre Node puro

✨

Código más limpio

Estructura simple y clara para escribir servidores en menos líneas de código.

🛣️

Manejo de rutas simplificado

Sistema de enrutamiento potente e intuitivo con métodos HTTP.

🔗

Middlewares

Sistema modular para procesar peticiones antes de llegar a la ruta.

🔌

Integración fácil

Compatible con bases de datos, autenticación, plantillas y más.

📥 Instalación de Express

# Paso 1: Crear el proyecto $ mkdir mi-proyecto $ cd mi-proyecto $ npm init -y # Paso 2: Instalar Express $ npm install express # Paso 3: Verificar package.json $ cat package.json

💡 npm init -y crea un package.json con valores por defecto sin hacer preguntas.

🚀 Servidor básico con Express

// archivo: server.js const express = require('express'); const app = express(); app.get('/', (req, res) => { res.send('¡Hola Mundo con Express!'); }); app.listen(3000, () => { console.log('Servidor en puerto 3000'); });

✅ ¡Mucho más simple que Node puro! Solo 6 líneas vs 8.

Bloque 3

Middleware en Express

Funciones que procesan las solicitudes antes de llegar a la ruta final. Tienen acceso a req, res y next.

3 tipos de middleware

🌐

De aplicación

Se ejecuta en TODAS las solicitudes.

app.use((req, res, next) => { console.log('Log'); next(); });
🛣️

De ruta

Solo en rutas específicas.

app.get('/admin', verificarAuth, (req, res) => {...} );
📦

De terceros

Librerías externas.

app.use(cors()); app.use(express.json());

Ejemplo: middleware de logging

const express = require('express'); const app = express(); // Middleware que registra cada solicitud app.use((req, res, next) => { console.log(`${req.method} ${req.url} - ${new Date().toISOString()}`); next(); // ← IMPORTANTE: pasar al siguiente middleware }); app.get('/', (req, res) => { res.send('Página principal'); }); app.listen(3000);

⚠️ Si olvidas llamar a next(), la solicitud se queda colgada para siempre.

Bloque 4

Manejo de rutas en Express

Express permite definir rutas con diferentes métodos HTTP: GET, POST, PUT, DELETE.

Los 4 métodos HTTP principales

// GET - Obtener datos app.get('/usuarios', (req, res) => { res.send('Lista de usuarios'); }); // POST - Crear datos app.post('/usuarios', (req, res) => { res.send('Usuario creado'); }); // PUT - Actualizar datos app.put('/usuarios/:id', (req, res) => { res.send(`Usuario ${req.params.id} actualizado`); }); // DELETE - Eliminar datos app.delete('/usuarios/:id', (req, res) => { res.send(`Usuario ${req.params.id} eliminado`); });

📌 Parámetros en rutas

// Parámetro de ruta con ":" app.get('/usuario/:id', (req, res) => { res.send(`Usuario con ID: ${req.params.id}`); }); // Ejemplo: GET /usuario/42 // req.params.id === "42" // Múltiples parámetros app.get('/producto/:categoria/:id', (req, res) => { const { categoria, id } = req.params; res.send(`Categoría: ${categoria}, ID: ${id}`); }); // Query strings (después del ?) app.get('/buscar', (req, res) => { res.send(`Buscando: ${req.query.q}`); // GET /buscar?q=notebook → req.query.q === "notebook" });

📂 Servir archivos estáticos

Express puede servir HTML, CSS, JS e imágenes con express.static()

app.use(express.static('public')); // Estructura del proyecto: // mi-proyecto/ // ├── public/ // │ ├── index.html // │ ├── style.css // │ └── script.js // ├── server.js // └── package.json // Ahora los archivos son accesibles así: // http://localhost:3000/index.html // http://localhost:3000/style.css

AE 1.2 · Bloque 5

Arquitectura y flujo
de trabajo

Node.js usa un modelo single-thread con I/O no bloqueante. Vamos a entender cómo funciona por dentro.

Modelo Single-Thread vs Multi-Thread

⛔ Modelo tradicional

Multi-thread: un hilo nuevo por cada solicitud.

  • Alto consumo de memoria
  • Bloqueos frecuentes
  • Difícil de escalar
vs

✅ Node.js

Single-thread + no bloqueante: un solo hilo para todo.

  • Bajo consumo de memoria
  • Sin bloqueos gracias al Event Loop
  • Excelente para alta concurrencia

💡 Non-blocking en acción

console.log("Inicio"); setTimeout(() => { console.log("Proceso asíncrono"); }, 2000); console.log("Fin"); // ⚡ Salida esperada: // Inicio // Fin // Proceso asíncrono ← aparece 2 segundos después

💡 Node.js NO espera los 2 segundos. Ejecuta el resto del código y vuelve al setTimeout cuando termine.

Bloque 6

El Event Loop

Mecanismo que permite a Node.js manejar múltiples operaciones asíncronas sin bloquear el hilo principal.

🔄 Las 6 fases del Event Loop

1
Timers → Ejecuta callbacks de setTimeout() y setInterval()
2
I/O Callbacks → Maneja operaciones de entrada/salida (archivos, red)
3
Idle, Prepare → Uso interno de Node.js
4
Poll → Maneja nuevas conexiones y operaciones en espera
5
Check → Ejecuta callbacks de setImmediate()
6
Close Callbacks → Ejecuta callbacks de cierre (socket.on('close'))

Ejemplo: lectura de archivo asíncrona

const fs = require('fs'); fs.readFile('archivo.txt', 'utf8', (err, data) => { if (err) throw err; console.log(data); }); console.log('Leyendo archivo...'); // ⚡ Salida esperada: // Leyendo archivo... // (contenido del archivo)

✅ Node.js no espera a que readFile() termine para ejecutar la siguiente línea.

Bloque 7

Callbacks, Promises
y async/await

Tres formas de manejar código asíncrono en JavaScript, evolucionando desde menos legible a más legible.

1️⃣ Callbacks (la forma antigua)

function obtenerDatos(callback) { setTimeout(() => { callback(null, "Datos obtenidos"); }, 2000); } obtenerDatos((error, datos) => { if (error) { console.error(error); } else { console.log(datos); } });

⚠️ El uso excesivo de callbacks anidados genera el "Callback Hell" 🔥, código difícil de mantener.

2️⃣ Promises (mejora)

function obtenerDatos() { return new Promise((resolve, reject) => { setTimeout(() => { resolve("Datos obtenidos"); }, 2000); }); } obtenerDatos() .then(datos => console.log(datos)) .catch(error => console.error(error));

✅ Más limpio que callbacks. Se pueden encadenar con .then().

3️⃣ async/await (el estándar moderno)

function obtenerDatos() { return new Promise((resolve) => { setTimeout(() => resolve("Datos obtenidos"), 2000); }); } async function mostrarDatos() { try { const datos = await obtenerDatos(); console.log(datos); } catch (error) { console.error(error); } } mostrarDatos();

✅ Sintaxis más limpia, parece código síncrono. Es lo que se usa hoy en día.

Bloque 8

Escalabilidad

Capacidad de una aplicación para manejar más carga sin comprometer el rendimiento.

Vertical vs Horizontal

⬆️ Escalabilidad Vertical

Mejorar el hardware del servidor existente.

  • Más CPU, más RAM
  • Más disco SSD
  • Simple pero con límites
vs

➡️ Escalabilidad Horizontal

Agregar más servidores y distribuir la carga.

  • Múltiples instancias
  • Escalable "infinitamente"
  • Requiere balanceo de carga

🖥️ Clustering en Node.js

Permite ejecutar múltiples procesos de Node.js en el mismo servidor, aprovechando todos los núcleos de la CPU.

const cluster = require('cluster'); const os = require('os'); const http = require('http'); if (cluster.isMaster) { const numCPUs = os.cpus().length; for (let i = 0; i < numCPUs; i++) { cluster.fork(); // Crear un worker por cada CPU } } else { http.createServer((req, res) => { res.end(`Respuesta del worker ${process.pid}`); }).listen(3000); }

⚖️ Load Balancing

Estrategia para distribuir el tráfico entre múltiples instancias del servidor.

🔄

Round Robin

Distribuye solicitudes de forma equitativa entre servidores, uno tras otro.

📊

Least Connections

Envía al servidor con menos conexiones activas en ese momento.

🔒

IP Hash

Usa la IP del cliente para siempre enviarlo al mismo servidor.

🛠️ Herramientas para Load Balancing

🌐

NGINX

Servidor proxy inverso que distribuye tráfico a múltiples instancias de Node.js.

⚙️

PM2

Manejador de procesos con balanceo de carga usando clustering interno.

☁️

AWS ELB

Servicio de balanceo de carga en la nube de Amazon Web Services.

Clustering vs Load Balancing

Estrategia¿Cómo funciona?¿Cuándo usarla?
Clustering Múltiples procesos en el mismo servidor Cuando queremos aprovechar todos los núcleos de la CPU en un solo servidor
Load Balancing Distribuye tráfico entre varios servidores Cuando la demanda de usuarios es muy alta y necesitamos múltiples servidores

💡 En la práctica, se combinan: cada servidor tiene clustering interno, y un load balancer distribuye entre los servidores.
